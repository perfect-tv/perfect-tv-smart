# ТЗ: IPTV-плеер Perfect TV для смарт-ТВ (LG webOS, Samsung Tizen, браузер)

Полноэкранный IPTV-плеер для телевизоров LG (webOS) с ТВ-гидом, архивом и напоминаниями. Поведение и вид — `docs/controls.md` (клавиши и окна) и `docs/design.md` (оформление); если они о чём-то молчат — решение записывается в них. План и что проверено — `docs/PLAN.md`.

## 1. Цели и границы

**Цели**
- Плеер для пульта LG (обычного и Magic Remote): эфир, архив (catchup), EPG, ТВ-гид, «Программа и архив», напоминания, избранное, скрытие, блокировка по PIN, настройки; русский и английский язык.
- Плейлист и программа загружаются **потоком** и сразу пишутся в хранилище: файл целиком в память не читается. Каналы и передачи появляются в интерфейсе по ходу загрузки.
- EPG по умолчанию — из плейлиста (`url-tvg` / `x-tvg-url`), можно добавить свои источники или заменить ими источники плейлиста.
- Работа на старых телевизорах: минимальная версия — **webOS 3.0** (2016, Chromium 38), см. §2.

**Не входит в первую версию**
- Телетекст (на webOS дорожку телетекста не получить ни из `<video>`, ни из hls.js без своего демультиплексора).
- Деинтерлейсинг шейдером, выбор видеодекодера, сторож зависания с переключением на программный декодер — декодер на webOS один, аппаратный.
- Главный экран ТВ (аналог рядов Android TV), голосовой поиск.
- TMDB (описания и баннеры) — фаза 6.
- Ввод адреса с телефона по QR.

Решено (согласовано с пользователем 2026-09-26): **минимум — webOS 3.0**. webOS 1–2 (WebKit, без нормального MSE) не поддерживаются.

Что из этого следует для кода:
- Chromium 38 не знает классов, стрелочных функций, `let/const` в нестрогом режиме, `async/await`, `fetch`, потоков `ReadableStream`, CSS-переменных, `Object.assign`, `Array.prototype.find/includes`, `String.prototype.startsWith/padStart`. Поэтому код — TypeScript, бандл собирает esbuild, а затем `tsc` переводит его в **ES5** (`async` → генераторы → конечные автоматы, `for…of` с `downlevelIteration`). Недостающее из библиотеки — `src/core/polyfills.ts`. Есть в Chromium 38: `Promise`, `Map`/`Set`, `Symbol`, `TextDecoder`, `Uint8Array`, IndexedDB, MSE, Canvas 2D, flexbox, `calc()`.
- Цвета и размеры — константы в коде (`core/ui/u.ts`), а не CSS-переменные.
- Проверка, что в сборке нет синтаксиса новее ES5, — `npm run check-es5` (разбор бандла парсером в режиме ES5).

### Сеть: CORS, заголовки, потоковая загрузка

- Упакованное приложение открывается с `file://`; LG прямо пишет, что у него нет CORS-источника, и для запросов к чужим серверам советует хостинг. На деле серверы без `Access-Control-Allow-Origin` отвечают ошибкой. Кроме того, из страницы нельзя поставить `User-Agent` и `Referer` (запрещённые заголовки), а каналы IPTV их требуют (`http-user-agent`, `http-referrer`, `#EXTHTTP`).
- Поэтому в пакет входит **JS-сервис** (`service/`, Node.js, id `top.rootu.perfecttv.service`): **локальный прокси** на `127.0.0.1:47380`. Приложение будит его через Luna (`luna://top.rootu.perfecttv.service/start`, подписка держит сервис живым, пока открыто приложение) и ходит в сеть через него. Прокси:
  - `GET /p?u=<url>&h=<json заголовков>` — запрос с заголовками и редиректами, ответ — как есть, с `Access-Control-Allow-Origin: *` (плейлист, EPG, сегменты HLS, ключи);
  - для `.m3u8` переписывает адреса внутри плейлиста на себя (сегменты тоже идут с заголовками канала);
  - `GET /s/open` и `GET /s/read?id=&max=` — чтение ответа кусками по запросу (сессия): так большой XMLTV читается потоком и на Chromium 38, где ответа XHR по частям не получить;
  - `GET /ping` — проверка.
- Сервис держит активность `keepAlive` (`activityManager`), пока приложение подписано на `start`: без запросов система выгружает JS-сервис через несколько секунд. Ответ на `start` и ошибки пишутся в журнал приложения. Не ответил при запуске (Node на слабом ТВ стартует долго) — прокси перепроверяется при первом запросе, которому он нужен.
- **О программе** (последний раздел настроек): версия, телеграм-канал, «Поддержать проект», исходный код на GitHub — каждая ссылка открывается окном с QR-кодом (на ТВ её не нажать), «Лицензии» — Perfect TV, hls.js (Apache 2.0), fflate (MIT), упоминание TMDB, товарные знаки LG и Samsung. Ссылки и лицензия — в `src/core/about.ts` (правовые файлы репозитория — `LICENSE`, `NOTICE`, `CONTRIBUTING.md`, `CLA.md`: вклад принимается только с согласием по CLA); пустая ссылка — пункта нет. Сторонний код в сборке поменялся — обновить `THIRD_PARTY` там же.
- **Журнал** (Настройки → Данные → «Журнал»): строки консоли, ошибки, запросы, ответ сервиса — для проверки на ТВ без кабеля (`core/log.ts`).
- Тот же файл прокси запускается на ПК обычным Node (`npm run proxy`) — для разработки в браузере и в симуляторе (симулятор JS-сервисы не запускает).
- Без прокси (сервис не отвечает) — прямой запрос: потоком через `fetch` + `ReadableStream` (Chromium 43+, webOS 4+), на webOS 3 — кусками `Range: bytes=` по 2 МБ (`XMLHttpRequest`, `responseType = arraybuffer`); сервер без Range — ответ целиком (только для небольших файлов: больше 64 МБ — ошибка «нужен сервис»).
- Сжатие: `Content-Encoding: gzip` снимает сам браузер / Node; файлы `.gz` (`1F 8B`) и `.zip` (`PK`, первый файл) распаковываются потоком (`fflate`) по сигнатуре первых байтов.

### Видео

- **HLS — hls.js 1.7** (MSE, есть с webOS 3), отдельным файлом `hls.min.js` (он уже в ES5). В начале `hls.min.js` — полифилы `core/polyfills.ts` для Chromium 38: hls.js в порядке загрузчика идёт до `app.js` и при инициализации вызывает `Array.from`. Почему не встроенный `<video>`:
  - встроенный плеер не отдаёт `#EXT-X-PROGRAM-DATE-TIME` — время кадра в архиве не узнать;
  - «растущий» (EVENT) плейлист Flussonic встроенный плеер начинает у края эфира, а позицию начала окна не отдаёт; hls.js даёт окно (`levels[].details.fragments`), `startPosition`, время кадра (`fragment.programDateTime`) и `seekable`;
  - ключевые кадры без IDR (I-кадры с recovery point у вещательных кодеров): демультиплексор hls.js считает ключевыми и non-IDR срезы I-типа, так что такие потоки стартуют.
- Встроенный `<video>` — для прямых ссылок (MPEG-TS по HTTP, MP4) и запасной вариант, если в канале hls.js упал с фатальной ошибкой медиа (например, звук MP2/AC-3, который MSE на модели не принимает: встроенный конвейер webOS декодирует их сам). Решение запоминается за каналом (`Prefs.playFix`), сбрасывается в меню канала.
- Канал с заголовками (`User-Agent`, `Referer`, `#EXTHTTP`) или с источником без CORS — через прокси (`/p?u=…&h=…`), иначе напрямую.

### EPG in Node (since 1.0.8)

The Node JS service fetches and streams XMLTV, decompresses gzip/ZIP-deflate,
parses channels and programmes, matches channel names/TVG IDs and writes
compressed programme packs directly into SQLite3. The GUI connects to the
existing local WebSocket at 127.0.0.1:47380/db and polls only progress and
metadata. There is no browser Worker in the active EPG path. Existing guide,
channels and user data are retained across update. If SQLite/WebSocket is not
available, new EPG cannot be saved and the UI should show a diagnostic error.

### Хранение

- **В 1.0.7 основной backend — SQLite3 в JS-сервисе** через WebSocket
  `ws://127.0.0.1:47380/db`; таблица `kv(s,k,v)` хранится в стандартном файле
  `/media/internal/perfecttv-data/perfecttv.sqlite3`. JS-сервис Node 0.12.2
  не использует native addons/WASM: таблица сериализуется и читается через
  встроенный ES5-модуль без исполнения SQL. Старые IndexedDB, Node-файлы и
  localStorage читаются лишь при миграции, в них больше не пишем.
- Содержимое: плейлисты с каналами, источники EPG, каналы XMLTV,
  программа, сопоставления, настройки, избранное, история, скрытое,
  блокировки, напоминания и резервная копия.
- Программа хранится **пачками по каналу**: запись
  `{s, x, l, n, p:[[start, stop, title, sub, desc, cat, icon], ...]}`.
  Чтение программы — по диапазону `[s,x]`; старые загрузки удаляются после
  успеха. Окно хранения: от `сейчас − (глубина архива + 1 сутки)`
  до `сейчас + 8 суток`. Прошедшая программа прежней загрузки, которой нет
  в новой (XMLTV часто отдаёт только с сегодняшнего дня), переносится в новую
  в пределах этого окна; старше окна не хранится.
- Синхронный API настроек поддерживается RAM-кэшем, который наполняется из
  SQLite до показа интерфейса и сбрасывается в базу через WebSocket.

### Пульт

- Клавиши — `keydown` / `keyup` на `document`, `keyCode`. Коды LG: ← ↑ → ↓ 37–40, OK 13, «Назад» 461 (чтобы получить её, в `appinfo.json` — `"disableBackHistoryAPI": true`), CH+/CH− 33/34, цифры 48–57, красная/зелёная/жёлтая/синяя 403–406, ▶ 415, ⏸ 19, ⏹ 413, ⏪ 412, ⏩ 417, INFO 457, GUIDE 458. Клавиши «Меню» у пульта LG нет (кнопки «Настройки» и «Q.Menu» система приложению не отдаёт) — меню канала открывается удерж. OK и **красной** кнопкой (`docs/controls.md`). Автоповтор `keydown` пульт LG присылает; долгие нажатия и удержание ↑/↓ считает `ui/keys.ts` по своим таймерам, как в Android-версии.
- **Magic Remote**: курсор — события мыши; `cursorStateChange` (`event.detail.visibility`) — курсор показан/скрыт. Пока курсор виден, работают клики и колесо (гид — каналы, окна — прокрутка), фокус пульта не сбрасывается. Стрелки скрывают курсор и работают как обычно.
- Выход: `PalmSystem.platformBack()` (возврат в лаунчер); в браузере — `window.close()`.

### Ядро и платформы

Решено (2026-11-15): общий каркас для других ТВ — Tizen, затем VIDAA, Titan OS и MSX (у последних трёх приложение открывается как страница по адресу). Код делится на ядро и платформы:
- `src/core/` — всё общее: интерфейс, клавиши, языки, разбор M3U и XMLTV, архив, данные, плеер. Ядро не знает, на чём запущено, и не импортирует `src/platform/` (тест `tests/layout.test.ts`).
- `PlatformApi` (`src/core/platform.ts`) — всё, чем ТВ отличаются: прокси (`proxy`), хранилище настроек (`kv`) и записей (`db`), своя загрузка и чтение программы (`epg`), плейлист с телефона (`qr`), выход, курсор пульта, движок HLS по умолчанию, умеет ли встроенный плеер HLS (`nativeHls` — для отката с HEVC), размер данных.
- Необязательное (`proxy`, `epg`, `qr`) у платформы может быть `null`. Тогда ядро делает это само: только прямые запросы; программа разбирается в браузере (`Loaders.loadEpg`) и читается из `db`; поиск по программе — по каналу за раз; пункта «С телефона» нет. Строки «Прокси» и «Режим прокси» в настройках показываются, только если у платформы есть прокси.
- Платформа — папка `src/platform/<имя>/` с точкой входа сборки (`main.ts`: `usePlatform(...)`, затем `startApp()`). webOS — `src/platform/webos/`: Luna, JS-сервис (прокси, WebSocket-хранилище, программа, QR), перенос данных старых версий. Пакет webOS (`appinfo.json`, `service/`, `assets/`) пока лежит в корне.
- IndexedDB-хранилище записей (`src/core/data/idb.ts`) — общее: для платформ без своего хранилища, на webOS — только чтение данных до 1.0.7.
- Платформа `browser` (`src/platform/browser/`, сборка `npm run build:browser` → `dist-browser/`) — обычный браузер и ТВ, где приложение — страница по адресу (VIDAA, Titan OS, MSX). Настройки — localStorage (ключи `ptv:…`), записи — IndexedDB, программа разбирается в воркере (§5), оглавление суток — по базе. Прокси — внешний, тот же протокол, что у сервиса webOS (`/ping`, `/p?u=&h=`): адрес — параметр `?proxy=` ссылки запуска, запоминается в браузере; без него серверы без CORS недоступны (ошибка с подсказкой, «Прокси: не задан» в настройках). QR нет. Движок HLS по умолчанию — hls.js, без MSE — встроенный. Курсор — пока двигают мышь/указку и 3 с после. MSX — стартовый параметр `perfect-tv.github.io` (с замком HTTPS): `site/msx/start.json` → меню `site/msx/menu.json`, которое сразу открывает приложение действием `link:`; выход — в начало истории вкладки (обратно в MSX).
- Платформа `tizen` (`src/platform/tizen/`, `npm run build:tizen` → `dist-tizen/` с `config.xml`; пакет `.wgt` — `npm run package:tizen`, нужен Tizen Studio и профиль сертификатов). Решено (2026-11-16): минимум — **Tizen 3.0** (ТВ 2017+, Chromium 47+, есть MSE); Tizen 2.x (WebKit) — нет. Как `browser`, но: `<access origin="*">` — чужие серверы без CORS; прокси нет (у упакованного приложения нет адреса страницы, а свой сервис на Tizen — только у партнёров Samsung); «плеер телевизора» — AVPlay (§8): он ставит `User-Agent` и `Cookie` канала, а `Referer` и прочие заголовки — нет (в API Samsung их нет); канал с User-Agent или Cookie поэтому играет только через AVPlay (§8); клавиши сверх стрелок/OK/«Назад» регистрируются (`tizen.tvinputdevice`, docs/controls.md), «Exit» — выход; заставка выключается, пока видео играет (`webapis.appcommon`, `$WEBAPIS/webapis/webapis.js` в index.html); пакет `PrfTVrootu`, приложение `PrfTVrootu.PerfectTV`.
- **Плейлист с телефона по QR без своего сервера на ТВ** (browser, Tizen; на webOS страницу отдаёт сервис) — WebRTC (`src/core/qrrtc.ts`, страница телефона `site/send/` → `perfect-tv.github.io/send/#<id>.<ключ>`). Телефон создаёт предложение, ТВ отвечает; сигнализация — публичный ntfy.sh (ТВ слушает свою тему по WebSocket, телефон — свою, сообщения — простой POST с `?cache=no`: сервер не хранит). Ссылка идёт телефон → ТВ по каналу данных (DTLS), сервер видит только SDP; ключ из QR проверяется. Облачный PeerJS не подошёл: закрывал соединение на любое пересылаемое сообщение. Старые движки (`webkitRTCPeerConnection`, Chromium 38–55) — только вызовы с callback, новые — только Promise (смешивать нельзя). Нет WebRTC — кнопки «С телефона» нет. Телефону нужен интернет; ТВ и телефон лучше в одной сети (иначе — через STUN).
- **QR для программы (EPG):** «Источник программы» → «С телефона (QR)» — то же окно с видом `epg` (`QrInbox.open('epg')`): WebRTC — `#…​.e` в адресе страницы телефона (одно поле «Адрес программы XMLTV»), webOS — `/qr/new?kind=epg` (форма сервиса без названия).
- **Только HTTPS** (`Net.httpsOnly()`: страница по `https:` и прокси нет — сборка browser с сайта): браузер не загрузит `http://` (смешанное содержимое) — ни плейлист, ни программу, ни потоки. Так и пишется: подсказка в окне первого запуска, адреса `http://` не принимаются (ввод, QR, источник программы — тост с объяснением), ошибка загрузки такого плейлиста — тот же текст, страница телефона (`.s` в адресе) предупреждает и не отправляет `http://`, `/about/` — тоже.

### Обновление без переустановки (webOS, Tizen)

Решено (2026-11-18): пакет (`.ipk`, `.wgt`) — оболочка с загрузчиком, код приложения обновляется с сайта. Переустановка нужна только для нового загрузчика, прав в `config.xml` / `appinfo.json` или нового API сервиса webOS.

- **Загрузчик** — `loader.js` в пакете (`src/loader/run.ts` + хранилище платформы: `src/platform/webos/loader.ts`, `src/platform/tizen/loader.ts`); `index.html` запускает только его. Он берёт скачанный код, если тот целый, подходит оболочке (`shell` ≤ `SHELL` в `core/codever.ts`), не числится сбойным и **новее встроенного**; иначе — встроенные `hls.min.js` и `app.js` пакета. Сайт для запуска не нужен: нет связи / GitHub недоступен — запуск как обычно (скачанным, если он есть, иначе встроенным).
- **Где лежит скачанный код.** webOS — файлы сервиса (`<папка данных>/code/current`, `service/codestore.js`): браузерное хранилище webOS переполняется (§ «Хранение»). Загрузчик читает файлы по Luna кусками (`codeRead`, 128 К символов), метка запуска и сбойные версии — `codeState` (`state.json`). Tizen — IndexedDB `ptv-code` (`platform/tizen/codestore.ts`), метки — localStorage.
- **Проверка** — в коде приложения (`core/codeupdate.ts`): через минуту после старта и раз в 12 ч (настройка «Обновлять автоматически», по умолчанию вкл.) и по OK на «Обновление» в «О программе». `https://perfect-tv.github.io/<webos|tizen>/version.json` — запросом браузера (с проверкой сертификата): `version`, `shell` (нужный протокол оболочки), `service` (нужный API сервиса webOS, `SERVICE_API` в `service/proxy.js`; сервис сообщает свой в `/ping` и Luna `ping`), `files` (sha256 и размер `hls.min.js`, `app.js`). Новее запущенной и подходит — скачивается: на webOS — самим сервисом (`codeFetch`: адрес и sha256 от приложения, файлы в `staging`, все сошлись — становятся `current`), на Tizen — приложением (sha256 — свой, `core/sha256.ts`: WebCrypto в `file://` и на старых движках бывает недоступен). Нужен новый пакет — в «О программе» «есть X — нужно переустановить приложение». Применяется при следующем запуске; скачано — тост, в «О программе» OK — перезапуск сейчас. «Версия из пакета» — забыть скачанное.
- **Сбой.** Перед запуском скачанной версии — метка «запускается X»; код снимает её первым делом (`ptvLoader.ok()` в `startApp`). Ошибка до этого — X в сбойные, перезапуск встроенным; метка осталась с прошлого раза (завис) — так же при следующем старте. Сбойная версия больше не ставится; откат — на встроенную (предыдущая скачанная заменяется новой).
- **API оболочки** — `window.ptvLoader` (`shell`, `builtin`, `version`, `source`, `ok()`, `bad()`). Менять его, файлы пакета, нужные коду, или права — повышать `SHELL`; новое от сервиса webOS — `SERVICE_API`. Код с файлом воркера из пакета (`epg-worker.js`) при скачанной версии не запускает (протокол мог измениться) — только из Blob, иначе разбор в основном потоке.
- **Сайт** (`tools/build-site.mjs`): `webos/` и `tizen/` — `app.js`, `hls.min.js` и `version.json` той же сборки, что пакеты релиза. Повышение версии в `appinfo.json` и публикация сайта = обновление у всех с новой оболочкой (сайт без тега тоже публикуется — выпускать только готовое).
- Отладка: `window.ptvCodeSite = 'http://…/'` в DevTools — свой адрес сайта для проверки.

## 3. Данные

Все времена — unix-секунды. Модели (`data/models.ts`):

```
playlist   id, name, url, epgMode(0 — из плейлиста, 1 — плейлист + свои, 2 — только свои), userEpg[], headerEpg[],
           loadedAt, channelsCount, error
channel    num, key, name, url, group, logo, tvgId, tvgName, tvgShift, catchupType|null, catchupSource,
           archiveDays, userAgent, referrer, headers{}
epgSource  url, loadedAt, loadId, etag, lastModified, error, count
epgChannel s, id, names[], icon
programme  [start, stop, title, subTitle, desc, category, icon]
```

- **Ключ канала** `key` — нормализованное имя (`Names.key`): на нём держатся избранное, история, скрытое, блокировки, очки и напоминания, поэтому они переживают перезагрузку плейлиста.
- Источник EPG общий для плейлистов: один URL скачивается один раз.
- Перезагрузка плейлиста: пока идёт, интерфейс показывает старый список; по окончании — замена одной записью.

## 4. Плейлист (M3U/M3U8)

Потоковый разбор построчно (`data/m3u.ts`), правила — как в Android-версии:
- `#EXTM3U` — атрибуты заголовка: `url-tvg`, `x-tvg-url`, `tvg-url` (несколько URL через запятую или пробел), `catchup`, `catchup-type`, `catchup-days`, `catchup-source`, `tvg-rec`, `timeshift`, `tvg-shift`.
- `#EXTINF:-1 attrs,Название`: название — после первой запятой вне кавычек (в `http-user-agent` бывают запятые). Атрибуты `key="v"`, `key='v'`, `key=v`, ключи без учёта регистра.
- `#EXTGRP:` — группа следующих каналов без `group-title`; `#EXTVLCOPT:http-user-agent/http-referrer`; `#EXTHTTP:{json}`.
- Строка URL (http, https, rtmp, rtsp, udp, rtp, mms) завершает канал; YouTube пропускается; без `#EXTINF` — имя `Ch N`; значки `ⓢⓖⓥⓞ` убираются.
- Архив: `catchup-days` / `tvg-rec` / `timeshift` у канала или в заголовке, `catchup-enable`, явные `catchup` / `catchup-type` / `catchup-source`; `catchup="disabled"` выключает. Глубина не указана — настройка «Глубина архива по умолчанию».
- BOM, CRLF, gzip, обрыв на середине — тесты `tests/m3u.test.ts`.
- Ошибки `no_url | network | http_<код> | format | empty | need_service` — экран ошибки с «Повторить» и «Настройки».

## 5. Программа (XMLTV)

Свой разборщик на уровне байтов (`core/data/xmltv.ts`), по кускам `Uint8Array` любой длины: тег на границе кусков доклеивается. У `<programme>` читается открывающий тег; передача ненужного канала пропускается поиском `</programme>` по байтам без декодирования; нужная копируется и разбирается (title, sub-title, desc, category, icon, `lang`, сущности, CDATA). Кодировка — из пролога (UTF-8 или windows-1251, `TextDecoder`).
- Время `yyyyMMddHHmmss ±hhmm` (смещения может не быть — UTC; секунд может не быть). Нет `stop` — конец по началу следующей; перекрытия обрезаются.
- Языки: язык интерфейса, затем `ru`, затем первый.
- Фильтр: на первом `<programme>` каналы плейлиста сопоставляются с `<channel>` (§6), передачи остальных пропускаются.
- Кэш: `If-None-Match` / `If-Modified-Since`, `304` — не разбирать. Обновление — при запуске, если данным больше «Обновлять программу каждые» (по умолчанию 12 ч), и раз в 15 мин, пока приложение открыто.
- **Загрузка, распаковка и разбор программы — вне потока интерфейса.** У платформы своя загрузка (`PlatformApi.epg`; webOS — JS-сервис, дочерний процесс, §2 «EPG in Node») — она. Нет — воркер ядра (`core/worker/epg.ts`, клиент `core/data/epgworker.ts`): он качает, распаковывает и разбирает, а пачки (каналы XMLTV, сжатые пачки передач, сопоставление) отдаёт в основной поток; база пишется там (IndexedDB в воркере есть не везде — старый WebKit, Safari до 10), следующая пачка разбирается после подтверждения записи. Код воркера встроен в `app.js` строкой и запускается из Blob — так он работает и у приложения с `file://`, где `new Worker('файл')` запрещён (проверено на webOS 3, Chromium 38); не вышло — файл `epg-worker.js`; не ответил за 8 с — тот же разбор в основном потоке кусками с `setTimeout(0)` (`Loaders.parseEpg`). Iframe вместо воркера не годится: он в том же потоке. Внутри Blob-воркера действует CORS даже у приложения с `file://`: `Range` и условные заголовки (`If-None-Match`, `If-Modified-Since`) там вызывают OPTIONS, который простые серверы не умеют. Поэтому без потокового `fetch` порядок такой: куски `Range` по 2 МБ (память постоянна); отказ первого куска — один простой GET без своих заголовков (без 304), который читается по ходу загрузки (`progressiveStream`: текст в `x-user-defined`, байт = код символа & 0xFF; приём из epg.rootu.top/epgParser2.html). Цена — ответ копится строкой (сжатый, ~2 байта на байт), предел 128 МБ. Прокси в воркере — HTTP по адресу из основного потока (`ProxyApi.base`) и только с потоковым `fetch` (Chromium 43+). Цель — 300 МБ распакованного XML без зависания интерфейса и роста памяти (память — на одну пачку канала). Замер скорости — `tests/xmltv.bench.test.ts` (`XMLTV_FILE=…` — на настоящем файле).
- Прогресс — тихой строкой в гиде и в настройках источника.

## 6. Сопоставление каналов с EPG

По источникам плейлиста, в порядке приоритета: `tvg-id` == id (и без учёта регистра); `tvg-name` или имя == одно из `display-name` после нормализации (`Names.matchKey`: нижний регистр, без «(архив)», «телеканал», «канал», «тв», «orig», «50»; `(+2)` → `+2`; знаки → пробел; транслит похожих букв). `tvg-shift` (часы) сдвигает программу при показе.

## 7. Время

`Clock.now()` — unix-секунды с поправкой по заголовку `Date` ответов сервера (если расхождение больше 30 с). Часовой пояс — системный. Форматы: «Сегодня», «Вчера», «Завтра», иначе «Пн, 02.11».

## 8. Воспроизведение (`core/player/playback.ts`)

- Один `<video>` на всё время, hls.js создаётся на каждую ссылку и уничтожается при смене. Короткий старт (`maxBufferLength` 10 с для эфира), повтор при ошибке эфира через 2, 5, 10 с, затем «Канал недоступен».
- **Архив** — шаблоны `data/catchup.ts` (тот же набор, что в Android-версии: `shift`/`timeshift`, `append`, `default`, `flussonic*`/`fs`, `xc`, переменные `${start} ${utc} ${end} ${utcend} ${offset} ${duration} ${now} ${lutc} ${timestamp}`, `${(b)…}`, `${(e)…}`, `${(n)…}`, `(bu)`, `(b+3)`, `${(d)M|S|h|m}`), тесты `tests/catchup.test.ts`.
- **Flussonic HLS**: передача моложе 6 ч — `archive-START-now.m3u8` (EVENT, дописывается — можно смотреть до края эфира без новых ссылок), старше — `archive-START-DURATION.m3u8` (VOD). `?event=true` не используется: балансировщики провайдеров (balelbrus) отбрасывают параметры и отдают VOD с концом «сейчас».
- **Позиция в архиве**: HLS с `#EXT-X-PROGRAM-DATE-TIME` — время кадра = `programDateTime` фрагмента + смещение внутри него (если правдоподобно: в пределах суток до «сейчас»); hls.js стартует EVENT-плейлист с `startPosition = 0` (начало окна), а если всё же начал у края — после загрузки плейлиста позиция ставится на начало окна. Без PROGRAM-DATE-TIME — `start + (позиция − base)`, где `base` — начало окна. Скорость — ровно 1.0.
- Перемотка внутри окна — `currentTime`, за пределами — новая ссылка; продолжение — по `ended`, при остановке на 15 с или при фатальной ошибке (не чаще раза в 15 с); догнали эфир — переход в эфир; ссылки не переиспользуются.
- **Пауза эфира**: позиция запоминается; после продолжения, если сдвиг больше 3 с, — «архив со сдвигом» (бейдж «Архив», «−0:45»): пока окно потока держит момент (HLS DVR) — им, иначе ссылка архива на момент паузы.
- Перемотка: нажатие — 30 с, удержание — скорость растёт (от 30 с до 10 мин эфира в секунду), применение через 0,9 с.
- Качество (SD/HD/FHD/4K) — по `videoHeight`. Звук и субтитры — дорожки hls.js (`audioTracks`, `subtitleTracks`); язык запоминается. Формат кадра — `object-fit` (вписать / растянуть / увеличить). Таймер сна — 15–120 мин.
- **Плеер телевизора** (настройка «Движок HLS»: hls.js / плеер телевизора / авто — эфир плеером ТВ, архив hls.js) — `video.src` или свой плеер платформы (`PlatformApi.nativePlayer`, интерфейс `NativeEngine`). На Tizen это **AVPlay** (`platform/tizen/avplay.ts`), по умолчанию «авто»: видео на своей плоскости под страницей (элемент `<object type="application/avplayer">` на месте `<video>`, `setDisplayRect` в пикселях 1920×1080); заголовки — `setStreamingProperty` после `open`, до `prepare`: `USER_AGENT` (канала, без него — UA браузера ТВ, а не `samsung-agent/1.1`) и `COOKIE`; `Referer` и прочие AVPlay не ставит (документация Samsung, AVPlay API: из заголовков запроса только эти два) — в журнал «native player ignores headers». Канал с заголовками, которые ставит встроенный плеер (`PlatformApi.nativeHeaders`), без прокси всегда играет им — и архив, и при настройке «hls.js», без отката на hls.js после ошибки (`headersForNative`): hls.js в браузере ТВ заголовков не ставит, провайдер отдал бы заглушку; готовность — первый `oncurrentplaytime`; ошибки — `onerror`/`prepareAsync` (связь → network, остальное → media, дальше — та же логика переключения на hls.js); звуковые дорожки — `getTotalTrackInfo`/`setSelectTrack`; формат кадра — `setDisplayMethod`; заставка выключена, пока играет. Субтитры AVPlay и время кадра по PROGRAM-DATE-TIME (его AVPlay не отдаёт — позиция архива по `start + (позиция − base)`) — нет.
- **HEVC и MSE**: hls.js не декодирует сам — для HEVC (`hvc1`/`hev1`) нужен MSE с его поддержкой. В журнал при каждом потоке пишутся варианты (разрешение, битрейт, `CODECS`, `VIDEO-RANGE`), контейнер сегментов (`fMP4`/`MPEG-TS`) и результат `MediaSource.isTypeSupported` для `hvc1`/`hev1` и 4K Main10; один раз за запуск — общая проверка MSE. Если в манифесте есть HEVC, а MSE его не принимает, а встроенный плеер умеет HLS (`video.src` на webOS, AVPlay на Tizen), канал автоматически переходит на него (`onUnsupportedCodec`, `hevcSupport` в `player/hlsmode.ts`), решение сохраняется как исправление канала (`Prefs.playFix`).

## 9. Интерфейс

Один экран: `<video>` и слои поверх (стек слоёв в `ui/tv.ts`); верхний слой получает клавиши. Обычные окна — DOM с классами из `ui/style.ts`, длинные списки и сетка гида — Canvas без выделения памяти на кадр. Масштаб: **1 em = высота экрана / 48** (как 10 dp при 480 dp в Android-версии), «Размер интерфейса» — 54 / 48 / 43,2.

Состав — как в Android-версии (`docs/controls.md`): инфопанель (затемнение, «ещё N мин», «Далее», закрепление ↓, описание ↓↓), карусель, набор номера, ТВ-гид (колонка категорий по ←, плейлисты, сетка 2 ч с линией «сейчас», виды «ТВ-гид» / «Каналы + программа» / «Категории + каналы» / «Каналы»), «Программа и архив», карточка передачи, недавние каналы, меню канала (шторка справа), окно PIN (кольцо, ряды, клавиатура), напоминания, «Управление», настройки (два столбца), мастер первого плейлиста (над формой — «Language:» — не переводится — и кнопка с названием языка, по OK список языков; поля адреса и имени; кнопки «Добавить», «С телефона (QR)» — окно QR-ввода, как в настройках, — и «Настройки»), экран ошибки, тост, поиск. Выделенное название, которое не влезает, прокручивается (бегущая строка, настройка «Бегущая строка»); другой плейлист из гида или меню сначала только показывается — видео играет, пока в нём не выберут канал.

**Ввод текста.** На webOS у `<input>` своя экранная клавиатура системы; поля форм (адрес плейлиста, PIN нового) — обычные `<input>`, фокус на поле открывает её. Поиск — своя клавиатура (как в Android-версии).

## 10. Нефункциональные требования

- Холодный старт до видео с последним каналом — меньше 3 с на webOS 4 (каналы — из IndexedDB, плейлист в фоне не перекачивается, если моложе 24 ч).
- Переключение канала ←/→: инфопанель — сразу, видео — через 0,7 с.
- Гид листается без рывков (сетка — один Canvas, перерисовка по `requestAnimationFrame`).
- Плейлист на 10 000 каналов и EPG на сотни МБ — без падения вкладки (память — пачка канала).
- Язык — русский и английский (`strings/ru.json`, `strings/en.json`, подстановки `%1$s`, счётные — формы `one/few/many/other`), по умолчанию — язык системы (ru/uk/be/kk — русский). Тест `tests/lang.test.ts` сверяет ключи и подстановки.

## 11. Проверка

- Юнит-тесты (Node, vitest): M3U, XMLTV (и замер скорости), шаблоны архива, сопоставление, клавиши, ячейки сетки, строки.
- Ручная: Chromium 1920×1080 с прокси на ПК (`npm run dev`), webOS TV Simulator 6.0 (`docs/PLAN.md`), архив Flussonic — `tools/flussonic_mock.py`.

### Оптимизация переключения (1.0.9)

- В дополнение к основной SQLite3 создана отдельная SQLite3 для настроек и
  пользовательских данных (`perfecttv-settings.sqlite3`); при первом старте
  копирование из старого файла. Все данные по-прежнему в SQLite, транспорт WebSocket.
- Основной большой SQLite-файл сериализуется с уступкой event loop через
  `setImmediate`, чтобы HTTP-прокси не оставался заблокированным на время записи.
- Для программы добавлен индекс в памяти по паре `(источник XMLTV, id канала)`.
- HLS по умолчанию на webOS: авто (нативный для эфира, hls.js для архива),
  один переход на hls.js при ошибке нативного воспроизведения.
