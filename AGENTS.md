# AGENTS.md — Perfect TV для LG webOS

Документация и комментарии — на русском. Проект самостоятельный: поведение и вид описаны в `docs/` — ТЗ (`docs/TZ.md`), управление (`docs/controls.md`), оформление (`docs/design.md`), план и что проверено (`docs/PLAN.md`). Чего там нет — решить и дописать туда же.

## Команды

- `npm run build` — сборка webOS в `dist/` (ES5, проверка парсером); `npm run dev` — то же с пересборкой при изменениях. `npm run build:browser` / `dev:browser` — сборка для браузера (VIDAA, Titan OS, MSX) в `dist-browser/` (README, «Проверка в браузере»); `npm run build:tizen` — Samsung в `dist-tizen/`, `npm run package:tizen` — `.wgt` (нужен Tizen Studio). `npm run build:site` — сайт perfect-tv.github.io в `site-out/` (в корне — приложение, `/about/` — инструкции) (публикует `.github/workflows/release.yml` по тегу `v<версия>` вместе с релизом `.ipk`/установщик/`.wgt`, README «Выпуск и сайт»).
- `npm test` — юнит-тесты (vitest): M3U, XMLTV, шаблоны архива, сопоставление, клавиши, ячейки, строки.
- `npm run typecheck` — проверка типов.
- `npm run proxy` — локальный прокси на ПК (для браузера и симулятора).
- `npm run package` — `.ipk` в `out/`.
- `npm run installer` — установщик на ТВ для людей: `out/PerfectTV-Installer-<версия>.zip` (Windows `.exe` + `.ipk` + инструкция; исходник — `tools/tv-installer`, Go 1.21+).

## Правила

1. **Только ES5 после сборки.** Минимум — webOS 3 (Chromium 38). Синтаксис пишем современный (его переводит tsc), но библиотечные функции новее Chromium 38 — только с полифилом в `src/core/polyfills.ts`. Нет `fetch`-потоков, CSS-переменных, `Object.assign` (полифил есть), `Array.prototype.includes` (полифил есть), `URL`, `AbortController`. Наследование от `Error` — с `Object.setPrototypeOf` (см. `NetError`).
2. **Плейлист M3U и программа — только потоком** (`Net.stream` → `Unpacker` → `M3uParser` / `XmltvParser`). Файл целиком в память не читать; программу писать пачками по каналу. Xtream Codes и Stalker/MAG — исключение: их API отдают JSON, он читается `Net.text` и разбирается в `data/xtream.ts` / `data/stalker.ts`; программа Xtream — обычный XMLTV (`xmltv.php`) и идёт потоком.
3. **Время** — `Clock.now()` (unix-секунды с поправкой по серверу), не `Date.now()` (кроме таймеров интерфейса).
4. **Интерфейс без фреймворков.** Окна — DOM (`core/ui/popups.ts`, классы из `core/ui/style.ts`), гид — команды рисования Canvas 2D (`core/ui/guide.ts`), которые по настройке «Отрисовка гида» идут либо в DOM (`core/ui/domctx.ts`, по умолчанию: элементы из постоянного набора, меняется только изменившееся), либо в `<canvas>`. Новое рисование в гиде — только тем, что умеет `DomCtx` (прямоугольники, `roundRect`/`strokeRoundRect`, текст, картинки, линии, `drawIcon`, обрезка прямоугольником, `translate`, `globalAlpha`), и проверять в обоих режимах. Размеры — в rem (1 rem = 1 em = высота / 48), цвета — `C` из `core/ui/u.ts`. Фокус — класс `f` (белый фон, чёрный текст), фокус браузера не используется.
5. **Клавиши** — через `Keys` и `Layer` (`core/ui/keys.ts`, `core/ui/layer.ts`). Раскладку менять вместе с `docs/controls.md` и окном «Управление» (`HelpLayer`).
6. Пользовательские данные привязаны к ключу канала `Names.key(name)`, а не к номеру.
7. **Строки — только `strings/<код>.json`** (`en` — основа, `ru` — поддерживается вместе с кодом, остальные языки — переводы, регистрация в `src/core/langs.ts`): `str('ключ', …)`, счётные — `plural`. Новый ключ — в `en` и `ru` (тест `lang.test.ts`); другие языки возьмут английский, пока не переведут (`npm run i18n`). Строки не кэшировать в полях модулей — язык меняется на ходу. Перевод — `docs/translating.md`.
8. Сеть приложения — через `Net` (прокси при заголовках канала и CORS). `service/proxy.js` — ES5 и только модули Node (на webOS 3 в сервисе Node 0.12).
9. **Ядро и платформы.** `src/core/` — общее для всех ТВ (интерфейс, данные, плеер, сеть) и не импортирует `src/platform/` (тест `layout.test.ts`). Всё, чем ТВ отличаются, — за `PlatformApi` (`src/core/platform.ts`): прокси, хранилище настроек и записей, своя загрузка программы, QR, выход, курсор. Реализация — `src/platform/<имя>/`, там же точка входа сборки (`main.ts`: `usePlatform`, затем `startApp`). Есть `webos`, `browser` и `tizen` (QR-ввод плейлиста без сервиса — WebRTC, `core/qrrtc.ts` + страница `site/send/`; tizen — как browser, но без CORS, без прокси, с регистрацией клавиш пульта и выходом по Exit; без сервиса: localStorage, IndexedDB, разбор программы в воркере ядра — `core/worker/epg.ts`, встроен в `app.js` и запускается из Blob; внешний прокси `?proxy=`); Luna, WebSocket и адреса сервиса — только в `webos`. Слова, зависящие от платформы (страница «Сеть», ошибка «нужен прокси»), — ключи строк в `PlatformApi.labels`. Чего у платформы нет (`proxy`, `epg`, `qr` = `null`), ядро делает само или прячет пункт.

## Тонкости

- **Архив Flussonic.** Передача моложе 6 ч — `archive-START-now.m3u8` (EVENT), старше — `archive-START-DURATION.m3u8`. `?event=true` не использовать: балансировщики отбрасывают параметры. hls.js стартует архив с `startPosition: 0`, время кадра — `fragment.programDateTime` (`Playback.wallClockMs`); `Tv.onReady` ставит позицию на начало передачи, если плеер начал не там.
- **CORS.** Упакованное приложение (`file://`) не получает ответы серверов без CORS и не может ставить `User-Agent`/`Referer`. Прокси переписывает адреса внутри `.m3u8`, чтобы сегменты шли с теми же заголовками.
- **Симулятор** JS-сервисы не запускает: для проверки в нём держать `npm run proxy` на ПК — приложение найдёт прокси на `127.0.0.1:47380`.
- **«Назад»** — код 461, приходит только при `"disableBackHistoryAPI": true` в `appinfo.json`.
- **Magic Remote**: курсор — события мыши, `cursorStateChange`; колесо — `wheel`.
- **С 1.0.9 настройки/история/избранное сохраняются в отдельной SQLite3 (`service/sqlite-settings.js`), чтобы запись последнего канала не пересобирала большую EPG; старые настройки копируются при первом старте. Программа загружается и разбирается в Node-сервисе** (`service/epgservice.js`): HTTP/XMLTV/gzip/zip, сопоставление и пакетная запись в SQLite. Браузер через `platform/webos/epg.ts` получает по WebSocket только прогресс и метаданные; обычный браузерный EPG Worker из 1.0.7 не запускается. `src/platform/webos/epg-entry.ts` компилируется в ES5 CommonJS `service/epg-parser.js` для использования того же XMLTV-парсера и matcher, что в TypeScript. Сервисное приложение не должно импортировать DOM.
- **webOS 3.** В `appinfo.json` не ставить пустые `requiredPermissions` / `requiredACG`: на webOS 3 приложению тогда запрещён вызов своего же сервиса («Denied method call … for category "/"»). Origin приложения там — `file://top.rootu.perfecttv` (на webOS 4+ — `file://` / `null`), проверки Origin в сервисе принимают оба. У JS-сервиса webOS 3 нет прав на `/media/internal` — папку данных выбирает `service/datadir.js` (первая доступная на запись, видна в ответе `ping`). Проверять на эмуляторах — README, «Эмуляторы webOS TV 3 и 4».
- **Заголовки канала на Tizen.** Прокси нет; AVPlay принимает из заголовков запроса только `setStreamingProperty('USER_AGENT' | 'COOKIE')` — после `open`, до `prepare` (состояние IDLE); `Referer` и прочие в документации Samsung не задаются. Канал с User-Agent или Cookie (`#EXTVLCOPT:http-user-agent`, `#EXTHTTP`) всегда играет через AVPlay — и в архиве, и при выбранном hls.js, без отката на hls.js (`PlatformApi.nativeHeaders`, `headersForNative` в `player/hlsmode.ts`); `Referer` теряется — в журнале «native player ignores headers».
- **Журнал** (`src/core/log.ts`) — первое, что смотреть, когда на ТВ что-то не так.

## Перед завершением

`npm run typecheck && npm test && npm run build && npm run build:browser && npm run build:tizen`. Изменения интерфейса — проверить в браузере 1920×1080 или симуляторе (снимок экрана).

## Хранилище (с 1.1.0)

Данные приложения хранит JS-сервис в файлах (`service/filekv.js`), интерфейс обращается к нему по WebSocket `ws://127.0.0.1:47380/db` (`src/platform/webos/socketdb.ts`). Браузерные IndexedDB и localStorage на webOS 4 упираются в квоту — новые данные туда не пишутся. Программа — файлом на канал в корзинах `prog2/<источник>/<ab>/<канал>/`, пачки дописываются в `.ndjson`, в конце загрузки канал собирается в один `.epg` — по gzip-куску на сутки с оглавлением в начале (`service/progfiles.js`). Браузер не держит программу канала целиком: `Repo.range` просит у `/prog?s=&x=&a=&b=` только нужные сутки (одни сутки — gzip-кусок как есть с `Content-Encoding: gzip`), кэш — куски «канал + сутки» с пределом по числу передач; поиск по программе — в сервисе (`POST /progsearch`). Не держать программу в памяти сервиса и не перезаписывать хранилище целиком. Всё, на что не ссылается ни один плейлист, сервис удаляет сам (`filekv.gc`). Разбор программы — в дочернем процессе (`service/epgrunner.js`). Сервис — ES5 для Node 0.12. Проверка сервиса: `npm run test:service`, а после правок сервиса или разбора программы — на настоящем Node 0.12: `tools/node012-check.js` (там же, откуда взять Node). Синтаксиса ES5 мало: в Node 0.12 `Buffer` ещё не наследник `Uint8Array` (нет `subarray`), нет `Uint8Array.prototype.slice`/`fill`, `String.prototype.startsWith`/`includes`, `Object.assign` — на этом разбор программы падал на webOS 4 («undefined is not a function»).
